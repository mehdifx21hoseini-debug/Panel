# قالب فایل پشتیبان (`.fitbak`)

نسخه‌ی قالب: ۱. پیاده‌سازی: `core/data/.../backup/` (تست‌ها: `BackupServiceTest`، `BackupCryptoTest`).

## بدون رمز

یک فایل ZIP معمولی است (با هر برنامه‌ی ZIP باز می‌شود):

```
manifest.json            مشخصات پشتیبان و checksum همه‌ی فایل‌ها
settings.json            تنظیمات (فعلاً پوسته)
data/<جدول>.json         یک فایل برای هر جدول پایگاه داده
photos/<نام فایل>        عکس‌های پیشرفت (از مرحله‌ی ۹)
```

### manifest.json

| کلید | معنی |
|---|---|
| `format` | همیشه `fitos-backup` |
| `formatVersion` | نسخه‌ی همین قالب (۱) |
| `createdAt` | زمان ساخت، میلی‌ثانیه‌ی UTC |
| `zone` | منطقه‌ی زمانی گوشی هنگام ساخت |
| `appVersionName`، `appVersionCode` | نسخه‌ی اپ سازنده |
| `schemaVersion` | نسخه‌ی پایگاه داده (`docs/database.md`) |
| `tables` | برای هر جدول: تعداد ردیف و مسیر فایل |
| `files` | SHA-256 (hex) هر فایل دیگرِ داخل ZIP |
| `photoCount` | تعداد عکس‌ها |

### data/&lt;جدول&gt;.json

```json
{ "table": "weight_entry",
  "columns": ["id", "day", "measuredAt", "zoneId", "weightKg", "condition", "note", "source", "createdAt", "updatedAt", "deletedAt"],
  "rows": [["…uuid…", 20746, 1792470600000, "Asia/Tehran", 89.4, "fasted", null, "manual", 1792470600000, 1792470600000, null]] }
```

مقدارها همان مقدار ستون‌های SQLite هستند: عدد صحیح، عدد اعشاری، متن یا `null` (ستون‌ها و واحدها در `docs/database.md`). ردیف‌های حذف نرم‌شده هم هستند (`deletedAt` دارند).

## با رمز

کل ZIP بالا رمزگذاری می‌شود. ساختار فایل:

```
هدر (۳۸ بایت):
  "FITOSENC" (۸) · نسخه = 1 (۱) · KDF = 1 (۱) · تکرارها (۴، big-endian)
  salt (۱۶) · پیشوند nonce (۴) · اندازه‌ی قطعه = 65536 (۴)
سپس قطعه‌ها، هرکدام:
  طول (۴، big-endian؛ بیت بالا = «قطعه‌ی آخر») · متن رمز + برچسب ۱۶ بایتی
```

- کلید: PBKDF2-HMAC-SHA256 با ۳۱۰٬۰۰۰ تکرار و salt تصادفی، کلید ۲۵۶ بیتی.
- رمزگذاری: AES-256-GCM روی هر قطعه‌ی ۶۴ کیلوبایتی؛ nonce = پیشوند ۴ بایتی + شماره‌ی قطعه (۸ بایت).
- داده‌ی همراه احراز اصالت (AAD): کل هدر + شماره‌ی قطعه + پرچم «آخر». پس هر تغییر در هدر، جابه‌جایی یا حذف قطعه‌ها، یا بریدن فایل شناخته می‌شود.
- **اگر رمز فراموش شود، فایل قابل بازیابی نیست.** رمز هیچ‌جا ذخیره نمی‌شود.

## مراحل بازیابی

1. تشخیص نوع فایل (هدر `FITOSENC` یا ZIP)، و در صورت نیاز گرفتن رمز.
2. باز کردن فایل در حافظه‌ی خصوصی اپ؛ فقط نام‌های مجاز پذیرفته می‌شوند (جلوگیری از مسیرهای مخرب)، با سقف تعداد و حجم.
3. بررسی `manifest.json`: قالب، نسخه (پشتیبان اپِ جدیدتر رد می‌شود)، SHA-256 همه‌ی فایل‌ها.
4. ساخت یک پایگاه داده‌ی جدا با Schema همان نسخه‌ی پشتیبان (از Schemaهای ثبت‌شده‌ی داخل اپ)، بارگذاری همه‌ی ردیف‌ها و مقایسه‌ی تعدادها.
5. باز کردن آن با Room: بررسی شناسه‌ی Schema و اجرای migrationهای خود اپ تا نسخه‌ی فعلی. پشتیبان‌های قدیمی از همین راه بازیابی می‌شوند.
6. پیش‌نمایش برای کاربر و تأیید.
7. ذخیره‌ی خودکار یک **نسخه‌ی ایمنی** از داده‌های فعلی (بدون رمز، فقط در حافظه‌ی خصوصی اپ، سه نسخه‌ی آخر).
8. جایگزینی همه‌ی جدول‌ها در یک تراکنش (کلیدهای خارجی در پایان تراکنش بررسی می‌شوند)، سپس عکس‌ها و تنظیمات.

اگر هرکدام از مراحل ۱ تا ۵ شکست بخورد، داده‌های فعلی دست‌نخورده می‌ماند.
